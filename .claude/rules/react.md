# React Rules

このファイルは、React・TypeScript・フロントエンド実装に関する共通ルールを定める。

## 基本方針

- 既存コンポーネント、既存のスタイル記述、既存の型定義を優先する。
- Issueの受け入れ条件に必要な最小限のUIだけを実装する。
- 将来の利用を想定したコンポーネントやHookを追加しない。
- 見た目だけでなく、操作性・レスポンシブ・アクセシビリティを確認する。

## TypeScript

- `any`を使用しない。型が不明な場合は`unknown`を使用し、適切に絞り込む。
- 型定義はコードと同じファイル、または`types/`配下に置く。
- APIレスポンスの型は必ず定義し、無検証で使用しない。
- `as`によるキャストは、型が確定できない場合を除いて使用しない。
- `!`（非nullアサーション）は、確実にnullでないと保証できる場合だけ使用する。
- `interface`と`type`は既存パターンに合わせる。

## コンポーネント

- 関数コンポーネントを使用する。クラスコンポーネントを新規作成しない。
- コンポーネントは表示と操作に集中させる。業務ロジックをコンポーネント内に直接記述しない。
- 複数箇所で利用される、または独立した明確な責務を持つUIにのみコンポーネントを作成する。
- 1回しか使わない小さなJSXを、理由なくコンポーネント化しない。
- PropsはTypeScriptの型で明示する。
- 現在必要なPropsだけを定義し、将来用のPropsを追加しない。
- コンポーネントファイルはPascalCaseで命名する。

## Hooks

- React標準のHooksを優先する。
- 複数コンポーネントで重複するロジックがある場合にのみカスタムHookを作成する。
- カスタムHookは`use`プレフィックスで命名する。
- `useEffect`の依存配列を省略しない。不要な再実行を避けるよう依存を最小化する。
- クリーンアップが必要な副作用は、`useEffect`の返り値で処理する。
- 状態が不要な処理に`useState`を使わない。

## 状態管理

- ローカル状態は`useState`、副作用は`useEffect`を優先する。
- グローバル状態管理ライブラリは、要件として必要な場合だけ導入する。
- 状態の置き場所は、必要とするコンポーネントの最小共通の親とする。
- サーバーデータのキャッシュと状態管理を混同しない。
- 状態の更新は不変性を保って行う。

## API通信

- APIのベースURLは環境変数（`VITE_API_BASE_URL`など）で管理する。
- APIのエラー、ローディング、成功の各状態を適切に処理する。
- ユーザーへローディング状態とエラーを表示する。
- 通信中の二重送信を防ぐ対策を行う。
- APIレスポンスの型を定義し、無検証で使用しない。
- 秘密情報をフロントエンドのコードやリクエストに含めない。

## ルーティング

- ルーティングライブラリは、要件として必要な場合だけ導入する。
- ルートは一元管理し、分散させない。
- 認証が必要なルートは、未認証時に適切にリダイレクトする。
- URLパラメータとクエリパラメータの型を適切に扱う。

## フォーム

- `label`と入力項目を適切に関連付ける。
- 必須項目は見た目とバリデーションの両方で判別できるようにする。
- エラー時も入力内容を保持する。
- 送信ボタンの文言は、実行される処理が分かる内容にする。
- 送信中は再送信を防ぐ。
- placeholderだけをlabelの代わりに使用しない。
- フォームライブラリは、要件として必要な場合だけ導入する。

## レスポンシブ

- モバイルを基準に実装し、必要に応じてブレークポイントで拡張する。
- PC表示だけを基準に固定幅を設定しない。
- 横スクロール、文字切れ、ボタンの押しにくさが発生しないようにする。
- 画面サイズによって操作できない機能を作らない。

## アクセシビリティ

- クリック操作には用途に応じて`button`または`a`を使用する。
- クリック可能な`div`や`span`を安易に使用しない。
- 画像には内容に応じた`alt`を設定する。
- 装飾目的の画像やアイコンは`aria-hidden="true"`を付与する。
- フォーカス表示を理由なく削除しない。
- 色だけで状態やエラーを伝えない。
- 見出しレベルを不自然に飛ばさない。

## セキュリティ

- `dangerouslySetInnerHTML`は使用しない。やむを得ない場合は内容をサニタイズした上で人間に確認する。
- APIから取得した値をそのままHTMLへ埋め込まない。
- 認証トークンはlocalStorageへ保存しない。httpOnlyクッキーを使用する。
- 外部URLへのリダイレクトは検証する。
- `target="_blank"`を使用する場合は`rel="noopener noreferrer"`を付与する。

## パッケージ・ライブラリ

- ライブラリは人間の承認なしに追加しない。
- 標準APIやReact標準機能で実現できる場合はライブラリを追加しない。
- ライブラリのバージョンを固定する際は、既存のバージョン管理方針に従う。

## Figma・設計との整合性

- Figmaや画面設計がある場合は、文言、構成、状態、余白、色、レスポンシブを確認する。
- 設計との差異を独断で作らない。
- 実装上の制約で差異が必要な場合は、人間へ報告する。
- 設計にない機能や状態を、便利そうという理由で追加しない。

## 禁止事項

- `any`型の使用
- クラスコンポーネントの新規作成
- 1回しか使わないUIの過剰なコンポーネント化
- 業務ロジックのコンポーネント内直接記述
- `dangerouslySetInnerHTML`の無検証使用
- 認証トークンのlocalStorage保存
- 人間の承認なしのライブラリ追加
- 要件にないアニメーションや機能の追加
- Issueと無関係な画面修正
