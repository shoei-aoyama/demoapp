# 🔍 review — コードレビュー

Issueの承認済み実装方針・変更差分・プロジェクト規約を照合し、方針逸脱・不要コード・セキュリティ上の問題を重大度別に報告する読み取り専用スキル。

## 使い方

```
/review 12
```

## パイプライン

```
前提: /implement 完了（対象Issueに承認済み実装方針が記録済み）
読込: Issueコメント / git diff / .claude/rules/*.md
出力: 重大度別レビュー結果
次:   PASSED→後続工程／CHANGES_REQUIRED→修正後に再実行
```

## レビュー観点（優先順）

1. 承認済み方針シートとの一致（スコープ外変更がないか）
2. Issueの受け入れ条件との一致
3. セキュリティ・データ保護
4. プロジェクト規約（`project-principles.md`/`laravel.md`/`blade-tailwind.md`/`issue-workflow.md`）との一致
5. コード品質
6. 不要コード・過剰設計の有無

## 重大度

- 🔴 重大：修正または人間の判断なしに後続工程へ進めない問題（方針逸脱、受け入れ条件未達、脆弱性など）
- 🟡 注意：品質・保守性に関わり人間の判断が必要な問題
- 🔵 提案：対応しなくても完了を妨げない任意の改善案

## 判定

`PASSED` / `NEEDS_DECISION` / `CHANGES_REQUIRED` / `BLOCKED`

## ルール

- コードは変更しない（指摘の自動修正なし）
- 指摘には対象ファイル・行番号・根拠（方針シート／Issue／規約）を明記する
- 根拠のない一般論や可能性だけの指摘はしない
- 他のスキルを自動起動しない
