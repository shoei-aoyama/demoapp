# 📝 commit — コミット

現在のブランチと`develop`とのコミット履歴から初回実装か追加修正かを判定し、適切な単位で変更をステージして日本語メッセージでコミットするスキル。

## 使い方

```
/commit
```

## パイプライン

```
前提: コミットしたい変更が存在すること
出力: Gitコミット
次:   /review（初回実装後）または /pr（追加修正後）
```

## 判定ロジック

`git rev-list --count develop..HEAD`の結果で分岐する。

| develop..HEAD | 扱い       | コミット単位                     |
| ------------- | ---------- | --------------------------------- |
| 0件           | 初回実装   | 変更ファイルを1ファイルずつ個別に |
| 1件以上       | 追加修正   | 関連する未コミット変更をまとめて1つに |

無関係な変更が混在する場合は自動でまとめず停止する。

## プロセス

1. 現在のブランチと作業ツリーを確認（`main`/`develop`上や競合が残っている場合は停止）
2. 変更内容と未追跡ファイルを確認し、秘密情報・生成物が含まれていないか確認
3. `develop`からのコミット数で初回実装/追加修正を判定
4. ファイルパスを明示してステージし、日本語メッセージでコミット
5. 作成したコミットと残っている未コミット変更を報告

## コミットメッセージ

```
<接頭辞>: <日本語の変更内容>
```

接頭辞: `feat` / `fix` / `refactor` / `docs` / `style` / `chore`

## ルール

- 承認なしにコミットしない
- `git add .` / `git add -A` / `--no-verify` / `--amend`は使用しない
- `main`・`develop`へ直接コミットしない
- 秘密ファイル（.env, .pem, .key）や不要な生成物をステージしない
- Push・Pull Request作成は行わない
