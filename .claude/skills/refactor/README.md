# 🔧 refactor — リファクタリング提案

対象Issueの変更差分と`/review`結果を分析し、挙動を変えずに今すぐ明確な利益がある最小限のリファクタリング候補（最大3件）だけを提案する読み取り専用スキル。

## 使い方

```
/refactor 12
```

## パイプライン

```
前提: /review 完了
読込: Issueコメント / git diff / 直近の/review結果
出力: リファクタリング提案（実施は人間の判断後）
次:   採用した提案だけを通常の指示で修正
```

## 対象範囲

- 現在のIssueで変更されたファイルと、それが直接利用する既存コード
- `/review`で指摘された箇所、または人間が明示的に指定した箇所
- リポジトリ全体を探索しない

## 提案条件（すべて満たすもののみ）

- 現在のコードに具体的な問題がある
- 今すぐ得られる明確な利益がある
- 外部から観測できる挙動・受け入れ条件を変更しない
- 現在のIssueと変更差分の範囲内で完結する
- 既存コードのパターンまたはLaravel標準の作法に沿う

「将来使うかもしれない」「拡張性が高まる」「一般的に綺麗」だけを理由にした提案はしない。Service/Repository/Interface/Trait/Helperなどの新規抽象化も、既に重複・責務集中が具体的に存在する場合を除き提案しない。

## 判定

`NO_REFACTOR` / `PROPOSAL_AVAILABLE` / `BLOCKED`

## ルール

- コードは変更しない（提案の自動実装なし）
- 提案は最大3件、優先順位順に提示する
- DBスキーマ変更・認証認可の仕様変更・新規パッケージ追加はリファクタリング対象外として人間へ差し戻す
- 必要な提案がなければ無理に作らず`NO_REFACTOR`とする
