# ⚙️ implement — 初回実装

Issueコメントの承認済み実装方針（`## 実装方針（承認済み）`）を読み込み、`develop`を最新化してIssue用ブランチを作成し、方針の範囲内で初回実装を行うスキル。

## 使い方

```
/implement 12
```

## パイプライン

```
前提: /analyze でIssueに承認済み実装方針が記録済みであること
読込: Issueコメントの「## 実装方針（承認済み）」
出力: Issue用ブランチ + ソースコード
次:   /commit
```

## 手順

1. Issue本文とコメントから最新の承認済み方針シートを取得（存在しなければ停止）
2. 未コミット変更があれば、対象Issueの「## 関連要件」記載パスとの一致だけを確認し、一致しない場合は停止
3. `develop`をfast-forward最新化
4. 方針シート記載のブランチ名で新規ブランチを作成（同名ブランチがあれば停止）
5. 方針シートの「変更・追加」範囲内で実装
6. 変更ファイルと方針外の変更（あれば）を報告

## 実装原則

- 方針シートの「変更・追加」の範囲を基準にし、「変更なし（スコープ外）」へ踏み込まない
- 不要な抽象化・共通化・レイヤーを追加しない
- 既存の命名規則・構成・実装パターンを優先する
- Migration作成は可、`migrate`等のDB状態変更コマンドは実行しない

## 対象外（このスキルが行わないこと）

- テストコードの作成・実行、Pint/Lint/静的解析/ビルド
- コードレビュー・リファクタリング
- コミット・Push・Pull Request作成
- `/review`など後続スキルの自動起動

## ルール

- 方針シートとIssue・既存コードに矛盾があれば推測で進めず停止する
- 方針外の変更を行った場合は完了報告で必ず明示する
