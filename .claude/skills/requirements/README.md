# 📋 requirements — 要件定義（プロジェクト大元・最初の1回のみ）

対話形式で要件をヒアリングし、プロジェクト全体の大元となる要件ドキュメントを作成するスキル。

**最初の1回だけ**使用する。個別の新機能・改善・保守の要件定義は`/make-docs`から始める。

## 使い方

```
/requirements
```

## パイプライン

```
前提: なし
出力: docs/requirements/（新機能）
      docs/maintenance/{ID}-{kebab-case}.md（保守運用）
次:   /more-requirements（初回チェーンの続き）。個別の機能追加は /make-docs から
```

## プロセス

1. ヒアリング（目的・背景・利用者・必要な挙動・受け入れ条件・対象外・制約を2〜3問ずつ）
2. 要件案を整理して承認
3. 承認後 Markdown でドキュメントを出力

## ルール

- 承認なしにファイル出力しない
- 大枠の合意に必要な粒度に留める
- 不明点を残さない
- 個別の機能追加のたびに再実行しない
