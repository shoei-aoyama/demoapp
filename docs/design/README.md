# 🎨 design/ — デザイン・基盤方針ドキュメント

## 役割

デザインシステム・トンマナ刷新など、特定の新機能や個別の修正ではなく、**プロダクト横断で恒久的に参照される方針**を格納するディレクトリです。
`/make-docs` スキルによって作成されます。

> 新機能の要件定義は `docs/requirements/`、運用中に見つかった不具合・軽微な改善は `docs/maintenance/` に格納します。

## 対象になるもの

- デザインシステム・トンマナの刷新
- カラー・タイポグラフィ・コンポーネントの方針変更
- 複数画面・複数機能にまたがるUI方針の転換

個別画面の文言修正やモーダル位置調整のような単発の手直しは `docs/maintenance/` を使う。

## ファイル命名規則

```
{内容}.md
例: design-system-renewal.md / color-palette.md
```

## 記載すべき内容

`/make-docs` の共通テンプレートに従う。

| 項目 | 内容 |
| --- | --- |
| **目的・背景** | なぜ方針変更が必要か |
| **利用者** | 影響を受ける画面・機能の範囲 |
| **必要な挙動** | 方針の具体的な内容、正常系・分岐・エッジケース |
| **受け入れ条件** | 前提・操作・期待結果が判定可能な文章 |
| **対象外** | 今回の方針に含めないこと |
| **制約** | 技術・運用・期限などの制約 |
| **技術設計** | 該当する場合のみ（DB・API・画面・構成・意思決定） |
| **未決事項** | 解消できなかった論点 |

## 関連スキル

```
/make-docs → /issue → /analyze → /implement
```
