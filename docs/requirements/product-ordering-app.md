# 商品注文デモアプリ

## 目的・背景

- 現在勤務している会社ではAIツールを業務で使用できないため、AIを活用したLaravel新規開発の実力を示す社内提案用のデモとして、小規模な商品注文アプリを作成する。
- 見せたいのは本格的な業務アプリの完成度ではなく、「要件定義 → Issue化 → 人間承認 → Claude Codeによる実装 → PR作成 → レビュー」というAI主体の開発フロー一連を実演できることである。

## 利用者

- 商品閲覧・カート操作はログインなしで誰でも行える。
- 注文手続き（カートからの購入）にはログインが必要。ログインは事前に用意された単一のテストアカウントのみで行い、新規会員登録機能は持たない。

## 必要な挙動

- 商品一覧画面で、販売中の商品を一覧表示する（商品名・価格・説明・画像を表示）。商品が1件もない場合は「現在販売中の商品はありません」と表示する。
- 商品一覧の各商品から商品詳細画面へ遷移できる。詳細画面では商品名・価格・説明・画像を表示する。
- 商品詳細画面から、常に数量1でカートに追加できる（商品一覧画面には「カートに追加」ボタンを置かない）。
- カート画面で、商品ごとの数量変更（1〜99の範囲、範囲外はエラー表示し変更しない）、個別削除、カート全体のクリアができる。
- カートに入っている商品が後から販売停止になった場合、カート画面でその商品に「販売終了」ラベルを表示し、数量変更を不可にする。
- カート内容を確認したうえで注文確定画面へ進める。カートが空の場合も注文確定画面は表示するが、カートが空である旨を伝え、確定ボタンを無効化する。
- カート画面で「注文手続きへ進む」を押すと、未ログインの場合はログイン画面へ遷移する。ログイン済みの場合はそのまま注文確定画面へ進む。
- 注文確定画面（`/checkout`）へ未ログインで直接アクセスした場合も、ログイン画面へ遷移する。
- ログイン画面でメールアドレス・パスワードを入力してログインできる。テストアカウントの情報と一致しない場合はエラーを表示し、メールアドレスの入力値は保持する。
- ログインに成功すると商品一覧画面へ遷移する。
- ログイン中はヘッダーに「ログアウト」リンクを表示する。押すとログイン状態が解除され、商品一覧画面へ遷移する。
- 注文確定画面に氏名・メールアドレスの入力欄は置かず、ログイン中のテストアカウントのname/emailをそのまま注文の氏名・メールアドレスとして保存する。
- カート内に販売停止商品が1件でも含まれる場合、注文は確定できず、対象商品を明示したエラーを表示する。利用者はカート画面で対象商品を削除してから再度確定する。
- 注文確定時点の商品価格を`order_items`へ保存する。以降に商品価格が変更されても、確定済み注文の金額は変わらない。
- 注文確定に成功すると、セッション内のカートを空にし、専用の注文完了画面を表示する。
- 同一セッション内で、自分の注文履歴を注文日時の新しい順に一覧表示できる。履歴には注文内容（商品名・数量・注文時点の価格）と注文日時を表示する。
- 注文履歴画面（`/orders`）と注文完了画面（`/orders/{id}/complete`）は、未ログインの場合はログイン画面へ遷移する。ログアウトしても同一セッション内の注文履歴（`order_ids`）自体は保持され、再度ログインすると同じ履歴を確認できる。

## 受け入れ条件

- [ ] 販売中の商品が1件以上ある状態で商品一覧画面を開くと、各商品の名前・価格・説明・画像が表示される
- [ ] 販売中の商品が0件の状態で商品一覧画面を開くと、「現在販売中の商品はありません」と表示される
- [ ] 商品一覧画面で商品を選択すると、その商品の詳細画面（名前・価格・説明・画像）が表示される
- [ ] 商品詳細画面で「カートに追加」を押すと、数量1でカートに反映され、カート画面で確認できる
- [ ] カート画面で商品の数量を1〜99の範囲内の値に変更すると、変更後の数量が保存される
- [ ] カート画面で商品の数量に0以下または100以上を入力すると、エラーが表示され数量は変更されない
- [ ] カート画面で商品を個別に削除すると、その商品がカートから消える
- [ ] カート画面で「カートを空にする」を実行すると、カート内の全商品が削除される
- [ ] カートに入っている商品が販売停止になると、カート画面でその商品に「販売終了」ラベルが表示され、数量変更ができなくなる
- [ ] 未ログインの状態でカート画面の「注文手続きへ進む」を押すと、ログイン画面へ遷移する
- [ ] 未ログインの状態で `/checkout` に直接アクセスすると、ログイン画面へ遷移する
- [ ] ログイン画面で正しいメールアドレス・パスワードを入力すると、ログインに成功し商品一覧画面へ遷移する
- [ ] ログイン画面で誤ったメールアドレスまたはパスワードを入力すると、エラーが表示されログインできず、入力したメールアドレスは保持される
- [ ] ログイン済みの状態でカート画面の「注文手続きへ進む」を押すと、注文確定画面へ進む
- [ ] ログイン中はヘッダーに「ログアウト」リンクが表示され、押すとログイン状態が解除され商品一覧画面へ遷移する
- [ ] カートが空の状態で注文確定画面を開くと、カートが空である旨が表示され、確定ボタンが無効化されている
- [ ] 注文確定画面に氏名・メールアドレスの入力欄はなく、ログイン中のテストアカウントの氏名・メールアドレスが注文として保存される
- [ ] カートに販売停止商品が含まれる状態で確定を押すと、注文は確定されず、対象商品を示すエラーメッセージが表示される
- [ ] カート内に販売停止商品が含まれない状態で確定を押すと、注文が作成され、注文時点の商品価格が`order_items`に保存される
- [ ] 注文確定に成功すると、専用の注文完了画面が表示され、同一セッションのカートは空になる
- [ ] 注文確定後、同一セッション内で注文履歴一覧を開くと、注文日時の新しい順に注文内容（商品名・数量・注文時点の価格）と注文日時が表示される
- [ ] 未ログインの状態で `/orders` に直接アクセスすると、ログイン画面へ遷移する
- [ ] 未ログインの状態で `/orders/{id}/complete` に直接アクセスすると、ログイン画面へ遷移する
- [ ] ログイン→注文→ログアウト→再度ログインすると、ログアウト前に確定した注文が注文履歴に表示される
- [ ] 各画面がTailwind CSSでスタイリングされ、デモとして提示できる見た目に仕上がっている

## 対象外

- ログイン・会員登録機能（将来のAI追加デモ候補）
- 商品カテゴリ・検索・絞り込み機能
- 管理画面（商品登録・編集・注文管理などの画面）
- 在庫数の管理、および同一商品への複数利用者の同時注文に対する排他制御
- 注文後のキャンセル・注文ステータス管理
- 税金の計算
- 配送先住所・電話番号などの追加入力項目
- 他デバイス・他ブラウザからの注文履歴参照（セッションを跨いだ参照）
- カート・注文確定画面での合計金額表示（商品ごとの価格のみ表示する）
- スマートフォン等でのレスポンシブ対応の動作保証（PCブラウザでの検証を前提とする）
- 会員登録（新規アカウント作成）機能
- 複数テストアカウント・アカウント切り替え
- パスワードリセット・ログイン状態の永続化（「ログインを保持する」等）

## 制約

- Laravel 11 + MySQL 8.4 + Docker の環境を使用する（環境自体は準備済み）
- 画面は Blade + Tailwind CSS で実装する（別フロントエンドは持たない）
- 画面デザインは Tailwind CSS を用いて実装し、社内デモとして見栄えの良いUIに仕上げる（配色・トンマナ等の詳細な方針は必要に応じて docs/design/ で別途検討する）
- カート情報は Session で保持し、DB に永続化しない
- テーブル構成は products / orders / order_items の3テーブルを基本とする
- 商品には販売停止フラグを持たせる
- ログイン認証は `config/test-accounts.ini` に定義した単一のテストアカウント（`name`/`email`/`password`）とメールアドレス・パスワードを直接比較する簡易実装とする
- `config/test-accounts.ini` は `.env` と同様に `.gitignore` 対象とし、リポジトリには実ファイルを含めない（ひな形として `config/test-accounts.ini.example` を用意する）
- [FYI] パスワードは平文で管理する。`.claude/rules/database.md`の「パスワードやトークンを平文で保存しない」という原則の例外として、本デモに限り人間の承認のもと平文管理とする
- 認証にusersテーブル・Eloquent Userモデルは使用しない（DBスキーマの変更なし）
